Shows: link file → IdeaSpider → middlewares (UA / AutoThrottle / BanAwareThrottle) → pipelines → Postgres, plus the new checkpointed backfill loop and shared script lib feeding both backfill_ideas.sh and weekly_refresh.sh.

Decisions

  • Link files: restored via git checkout (done)
  • Pacing: chunked resumable batches, not one 38-40h run
  • Login: full-text via VIC_ENABLE_LOGIN=true + real account credentials (env vars only, never committed)

Implementation plan (5 tasks)

1. Login smoke test — verify the existing login flow actually unlocks full report text on 3 real ideas before trusting it for the full backfill.
2. scripts/lib_vic_scrape.sh — extract duplicated docker/preflight/scrapy-runner logic out of weekly_refresh.sh into shared functions.
3. Rewrite weekly_refresh.sh — source the shared lib; default RESET_DB flips from 1 → 0 (no more weekly full wipe).
4. scripts/backfill_ideas.sh — checkpointed batch crawler (data/backfill_checkpoint.json), resumable, never truncates the DB.
5. Docs cleanup — delete SOLUTION_OPTIONS.md, rewrite the false "site blocking" section of SCRAPY_TUNING.md.

Explicitly out of scope

Proxies, VPN, Tor, CAPTCHA-solving, fingerprint spoofing — none of it is needed. The site isn't defending against us; the BanAwareThrottleMiddleware is the correct response mechanism if that ever changes.
