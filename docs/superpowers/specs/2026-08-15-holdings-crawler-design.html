Holdings Crawler Design — Dataroma + HedgeFollow

Status: draft — Aug 15, 2026. Companion, separate pipeline to the existing VIC idea-scraper.

1. Why a separate pipeline from VIC

VIC scrapes dated idea writeups (one author, one stock thesis, one date). Dataroma and HedgeFollow are 13F holdings aggregators: investor × quarter × company snapshots. Different shape, different cadence, different update cardinality. Forcing one schema across all three would corrupt VIC's data or flatten the holdings data. Decision: two independent pipelines, sharing infra (Scrapy project, DB, politeness helpers) but not the data model. Optional future join: by ticker/investor-name only, not a schema dependency.

3. Data model

erDiagram INVESTOR ||--o{ HOLDING : has COMPANY ||--o{ HOLDING : "held as" INVESTOR { int id PK string name string source "dataroma | hedgefollow" string source_slug "e.g. BRK" string profile_url } HOLDING { int id PK int investor_id FK int company_id FK date quarter_date bigint shares numeric value_usd numeric pct_portfolio string activity "buy/add/reduce/sell/hold" } COMPANY { int id PK string ticker string name }

No changes to existing Company, User, Idea, Description, Catalysts, Performance tables. Company is reused read/write (create-if-missing by ticker); everything else in this pipeline is new.

Known risk carried over from VIC: the VIC scraper is currently blocked by the site (ConnectionLost on all requests). Dataroma's WAF response to a bare curl is the same class of problem. First implementation step for each new spider is a manual probe (Scrapy shell / browser-header curl) to confirm access before writing full spider logic — not assumed to "just work" because robots.txt is permissive.

5. Testing

  • Unit tests: fixture HTML → parsed HoldingItem, mirroring existing VIC spider test style.
  • Schema validation script extended to cover Investor/Holding tables.
  • No UI/frontend surface in this spec — backend/data pipeline only, so no Playwright DOM verification loop applies (that rule is for ui_scope: true work).

Module design blocks

Module: DataromaSpider

ResponsibilityCrawl Dataroma's 83 superinvestor list + per-investor current + historical holdings pages, yield HoldingItems
InterfaceStandard Scrapy spider; output → HoldingPipeline
DependenciesShared politeness config (rate limit, UA/headers), HoldingItem
Size target<200 lines; parsing helpers factored out if needed

Module: HedgeFollowSpider

ResponsibilityCrawl curated subset of HedgeFollow funds, same output shape as DataromaSpider
InterfaceStandard Scrapy spider; output → HoldingPipeline
DependenciesCurated fund list (built from Dataroma investor names + HedgeFollow fund directory), shared politeness config
Size target<200 lines

Module: HoldingPipeline

ResponsibilityUpsert Investor/Company/Holding rows from HoldingItems, dedupe by (investor, company, quarter_date)
InterfaceScrapy item pipeline; reads HoldingItem, writes via SQLAlchemy session
DependenciesSQLAlchemy models (Investor, Holding, existing Company)
Size target<200 lines
